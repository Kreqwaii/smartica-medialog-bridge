Структурированный черновик (AI Extraction)

Рекомендованные направления по прайсу клиники

1. Чтение и запись протоколов ЭМК (DATA_* / EMR)

В МИС «Медиалог» 7.11 и 8.x пользовательские поля форм осмотра хранятся в таблицах вида DATA_* (привязаны к PATDIREC_ID и MEDECINS_ID). Коннектор считывает структуру активного шаблона и маппит поля complaints, anamnesis_morbi, status_praesens, diagnosis_mkb10, recommendations через параметризованные запросы pyodbc / ODBC Driver 17 for SQL Server.

2. Прайс-лист и направления (FM_SERV / FM_DIR / PATDIREC)

Синхронизация каталога услуг выполняется из таблицы FM_SERV (код услуги, наименование, стоимость, профиль) методом PUT /service-requests/catalog. При подтверждении врачом (POST .../commit) коннектор создаёт записи направлений в FM_DIR и связывает их с текущим визитом в PATDIREC с возвратом mis_order_id.

3. Версионирование правок врача

При нажатии «Сохранить карту в Медиалоге» вычисляется diff между AI-черновиком (source: smartica) и финальным текстом врача в полях формы. Итоговая версия отправляется в POST /encounters/{id}/versions для дообучения моделей и аудита качества.

Outbound-only архитектура без входящих портов

Модуль работает внутри контура клиники как Windows Service и инициирует только исходящие HTTPS-соединения (TLS 1.2+) к облачному API Smartica.ai. Открытие входящих портов на межсетевом экране или публикация БД Медиалога в интернет не требуются.

Локальная очередь отказоустойчивости (SQLite)

Все исходящие события (ack, commit, versions) буферизуются в локальной SQLite-очереди с экспоненциальным backoff при временной потере связи с интернетом. Идемпотентность обеспечивается ключами encounter_id и idempotency_key.

Тестовый стенд МИС «Медиалог»

Для отладки используется изолированный тестовый контур MS SQL Server с обезличенными шаблонами DATA_* и справочником FM_SERV. Кнопка запуска в интерфейсе Медиалога настраивается через встроенный скрипт формы (вызов локального HTTP-хендлера или CLI-обёртки).

Этап 1 (4–5 рабочих дней): Сценарий 1 — Launch Pull

Развёртывание Windows-сервиса, настройка ODBC-подключения к тестовой БД Медиалога, реализация POST /encounters/launch, polling GET /encounters?status=ready, запись в DATA_* и подтверждение ack.

Этап 2 (3–4 рабочих дня): Сценарий 2 — Направления

Выгрузка прайса из FM_SERV в PUT /service-requests/catalog, получение AI-подборок, создание направлений в FM_DIR / PATDIREC и подтверждение POST .../commit.

Этап 3 (2–3 рабочих дня): Сценарий 3 — Версии и прод

Фиксация правок врача в POST /encounters/{id}/versions, нагрузочное тестирование, перенос на боевой сервер клиники и передача регламента сопровождения. Полный цикл по 3 сценариям: 10–12 рабочих дней.
